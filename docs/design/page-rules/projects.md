# Projects Page Rules

## Direction

Projects should use clean software-studio case-study layout.

This page is for technical credibility.

## Each Project Should Include

- title
- one-sentence value proposition
- role
- timeline / status
- tech stack
- problem
- what was built
- outcome / metric
- link / detail / repo if available

## Visual Rules

- clean panels
- thin borders
- screenshot or system diagram if available
- compact metadata badges
- restrained accent
- readable hierarchy

## Avoid

- vague project descriptions
- only listing technologies
- overusing AI-generated illustration
- making project cards too poetic
- fake metrics
- generic SaaS feature grids that do not match the actual work
